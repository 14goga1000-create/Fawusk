# CustomAV 0.5 — обязательно прочитать перед внедрением

## Цель

Встроить CustomAV в Go-архиватор так, чтобы архиватор проверял архив **до распаковки и до публикации результата**, не выполняя ни один файл.

## Главный принцип

CustomAV — отдельный детерминированный security-core. Нейросеть архиватора может объяснять результат, но не должна самостоятельно отменять блокировку или объявлять файл чистым.

Поток:

```text
создание/открытие архива → CustomAV → JSON-результат → политика архиватора → распаковка или блокировка
```

## Быстрый вариант интеграции

В этом пакете есть reference engine на Python и Go-адаптер `go/customav`. Адаптер запускает scanner через `exec.CommandContext` **без shell** и читает JSON-отчёт.

Скопируй в релиз архиватора:

- `engine/custom_av_engine_v3.py`
- `engine/custom_av_engine_v4.py`
- `engine/custom_av_engine_v5.py`
- `engine/customav_signatures.json`
- `engine/libarchive_extract.py`

И используй Go-клиент из `go/customav`.

## Минимальное использование

```go
client := customav.New(customav.Config{
    Python:     "python3",
    EnginePath: "path/to/custom_av_engine_v5.py",
    SignatureDB: "path/to/customav_signatures.json",
    Timeout:    10 * time.Minute,
})

result, err := client.ScanPath(ctx, archivePath)
if err != nil {
    return err
}

if result.IsMalware() {
    // Не распаковывать и не публиковать архив.
}
```

## Политика вердиктов

- `SUSPICIOUS / DO NOT RUN` — блокировать распаковку и публикацию.
- `TEST SIGNATURE DETECTED` — это известный тестовый файл EICAR, не настоящий вирус. Для обычного режима можно показать предупреждение, для тестового режима — считать успешным детектом.
- `MODIFIED OR UNTRUSTED / MANUAL REVIEW` — не блокировать автоматически без настройки пользователя, но показать жёлтое предупреждение.
- `NO POSITIVE MALWARE INDICATORS` — разрешить только если источник и политика доверия это допускают.

## Где вызывать сканер

1. **Открытие архива:** проверить исходный архив до распаковки.
2. **Создание архива:** проверить временный `.part` файл до переименования в финальный архив.
3. **Распаковка:** если архив зашифрован, повреждён или содержит вложенные архивы — сообщить об ограничении.
4. **Вложенные файлы:** при необходимости отправлять отдельные entry во временный файл через `ScanReader`.

## Обязательные ограничения безопасности

- Не использовать `sh -c`, `bash -c` или конкатенацию shell-команд.
- Не запускать ни один файл из архива.
- Не следовать symlink/hardlink при распаковке.
- Проверять `../`, абсолютные пути и Unicode-маскировку.
- Ограничить глубину вложенных архивов.
- Ограничить число файлов и общий распакованный размер.
- Не удалять подозрительный оригинал автоматически — использовать карантин/копию.
- Сохранять SHA-256, размер, формат и путь entry в журнале.
- Не отправлять файлы во внешний сервис без явного согласия пользователя.

## UI

Для каждого entry показывать:

- зелёный `чисто`;
- жёлтый `ручная проверка`;
- красный `заблокировано`;
- серый `не проверено / пароль / лимит`.

Показывать причину: `rule`, `path`, `detail`, `sha256`. Не показывать пользователю только общий score без объяснения.

## Сигнатуры

`customav_signatures.json` содержит EICAR и может расширяться. Не добавляй широкие слова вроде `password`, `socket` или `http` как блокирующие сигнатуры — это даст много ложных срабатываний. Используй точные byte-signature, хэши или сочетания признаков.

## Важно

Reference engine — статический анализатор, а не полноценная sandbox. Он не может увидеть поведение, которое проявляется только после запуска. Для динамического слоя оставь отдельную sandbox-интеграцию в будущем.
