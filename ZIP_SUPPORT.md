# ZIP support — alpha 0.6

Reads single-volume unencrypted ZIP using Store (0), Deflate (8), BZip2 (12) or Zstandard (20 legacy / 93 standard). The Go ZIP reader handles ZIP64, comments, data descriptors and extra timestamps; central-directory limits are checked before it allocates untrusted metadata. Zstandard ZIP decoder has a 64 MiB window/memory ceiling.

Names: UTF-8 flag is respected; invalid flagged UTF-8 is rejected. Otherwise the standard CP437 map is used. Valid Unicode Path (0x7075) data overrides a legacy name only after its version/name CRC/UTF-8 checks. Other legacy code pages are not guessed. Relative backslashes become separators; harmless `.`/empty internal path components are removed. Absolute/UNC/drive/device names, any `..` component, unsafe Windows suffixes/characters, case ambiguity, symlinks/special entries and file/folder collisions are rejected. Duplicate identical directory entries with zero data are deduplicated; duplicate files still fail. All records are validated before a staging directory is created, including when Go reports ErrInsecurePath and returns a usable catalogue.

Listing validates catalogue structure, names, declared quotas and implemented methods, but **does not decompress all payload or check every CRC**. Extraction checks regular-file CRC/declared lengths through the standard ZIP stream reader; only after success is the new staged directory published. Existing destinations are not overwritten. Selected preview validates the catalogue and reads only the selected entry, with the same file CRC and preview size/type restrictions. CRC is corruption detection, not a signature or antivirus result.

Unsupported: password/encrypted/AES ZIP, multi-volume ZIP, Deflate64, ZIP-LZMA and other unimplemented methods. Unsupported variants report an error rather than silently dropping entries. Maximum 100,000 input records/paths, 64 MiB central directory, 8 GiB/file, 20 GiB total decoded file data; preview 1 GiB. A browseable catalogue is not proof that payload is intact or safe.

Table size is uncompressed regular-file bytes. Folder bytes are zero for payload accounting, while their central-directory/local records do occupy container space. Dates use stored ZIP metadata, converted to the local computer timezone for display; all-zero DOS fields without a usable extended timestamp show unknown, not an invented 1979 date. Implicit parent directories have no invented timestamp.

Independent Python-produced Store/Deflate/BZip2 fixture bytes are preserved as Base64 literals in archive_fixtures_test.go; tests materialise them in temporary directories. Additional Go tests cover Unicode/CP437/path extras, Windows paths, harmless dot prefixes, true ZIP64 end structures, Zstandard methods, zero files/directories, duplicate directories, encrypted/unsupported methods, corrupt CRC and traversal. This is not a guarantee for every archive producer or legacy charset.
